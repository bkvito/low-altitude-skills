# Skill 合集仓库骨架搭建思路文档

## 核心思路

本次搭建采用轻量优先的方式，只创建当前阶段真正有用的目录和文件。

Skill 合集项目的核心产物是 `skills/{skill-name}/SKILL.md`。因此本次没有引入自动化脚本、上游同步目录或包管理配置，而是先保证后续可以稳定新增和维护 Skill。

## 取舍说明

没有创建 `scripts/`、`sources/`、`vendor/`、`instructions/` 和 `meta.ts`，因为这些目录主要服务于自动同步、批量生成和外部来源管理。当前用户的目标是先开始写具体 Skill，因此这些高级结构可以延后。

创建 `skills/_template/` 是为了降低后续新增 Skill 的重复成本。模板目录能统一 `SKILL.md` 的 frontmatter、正文结构和 `references/` 拆分方式。

创建 `AGENTS.md` 是为了让后续 AI Agent 在这个仓库里工作时有明确规则，避免目录结构、文档命名和验证流程变得不一致。

## 验证思路

验证重点不是运行构建命令，而是确认文档型仓库的结构完整性：

1. 文件存在。
2. Markdown 内容可按 UTF-8 正常读取。
3. 模板中的引用路径能对应到实际文件。
4. Git 能识别新增文件。

## 结果判断

当前骨架已经满足开始编写具体 Skill 的需要。后续只要复制 `_template` 目录并替换名称、描述和参考资料，就可以逐步扩展 Skill 合集。
